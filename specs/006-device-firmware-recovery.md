# SPEC-006：USB 小电视黑屏恢复

- 日期：2026-11-03
- 设备：ESP32-S3，MAC `d8:3b:da:4a:e9:84`，8MiB Flash / 8MiB OPI PSRAM。
- 用户确认：黑屏前显示 Kimi 额度看板；相关文件位于同级 `kimi-pocket` 项目。

## 1. 故障与证据

设备仍能 USB 枚举、响应 esptool 并运行 Desk Sprite 填色循环，但用户报告屏幕完全不亮。初始化成功日志不能证明实际接线正确。

当前固件使用 MOSI39/SCLK38/CS21/DC45/RST40/BL46。QuotaClock 的 SD2 参考配置使用 MOSI1/SCLK18/DC17/RST6/BL2，两者不一致。参考配置尚不等于已做 PCB 连通测量；通过恢复旧镜像和实物观察验证故障范围。

## 2. 恢复契约

1. 先读取当前完整 8MiB Flash 到本地忽略目录，核对容量并使用设备端 Flash 校验验证备份；失败则不写入。
2. 使用用户已有的 `../kimi-pocket/firmware_build/kimi_pocket_sd2_s3_verified.bin`，完整镜像长度 8,388,608 字节，SHA256：`b80ab84c9d62ac119ca38e395f23266bfceb542859599597e012ecbd661645a6`。
3. 验证 ESP32-S3 镜像头与镜像校验，核对分区无越界。文件名 verified 不是本次实机验证结论。
4. 将完整镜像恢复到地址 0，保留镜像中的原始 Flash 头参数；不单独擦除、不更改 eFuse。
5. 写入时执行完整 Flash 校验，再捕获启动状态。应用开始运行后 NVS 可变化；后续校验应区分程序/资源区和运行时配置区。所有诊断退出路径必须复位回应用并关闭串口。完整备份可恢复到写入前状态。
6. 只有用户看到屏幕恢复才算显示验收通过；联网、额度新鲜度另行验证。

## 3. 数据边界

Flash 备份及恢复镜像可能包含 Wi-Fi 配置，保存在 `kimi-pocket/firmware_backup/`、`firmware_build/` 的 Git 忽略目录，不输出 NVS 内容、不提交二进制。新备份权限为 600。公开记录只保留校验值、分区、去敏后的启动结论。

## 4. 验收

| 项目 | 通过条件 |
| --- | --- |
| 可回滚 | 当前完整镜像保存成功，长度正确且设备端校验一致 |
| 可刷写 | 本地镜像写入成功且设备端完整校验一致 |
| 启动 | 恢复后应用启动，无连续崩溃重启 |
| 屏幕 | 用户确认实物亮起并显示界面 |
| Kimi 看板 | 看板出现；真实额度需桥接服务及网络另行核验 |
