## 1. 目标与范围

让小电视里的角色根据工作状态和真实事件做出可辨认的动作。沿用粉白樱花房间、sakura-green 原角色、顶部状态、对话条与底部额度；通知结束后回到最新工作状态。

当前共享 C 渲染器只有睁眼、闭眼两幅角色资源，加一像素呼吸；工作主要增加电脑，庆祝主要增加星光，睡眠主要切夜景。上述效果是实现基线，不等同于完整角色动作。

首版包含六类动作：待机、工作、开心、叹气、警觉、睡眠；另保留协议已有的会议安静状态。成功标准是隐藏文字和场景装饰后，仍能通过角色姿态区分工作、开心、叹气、警觉、睡眠。

本规范细化 SPEC-003 的动作、资源和渲染契约；通知过滤、确认及音频规则继续遵循 SPEC-002/003。旧文档的等待队列容量 3 与当前 `ALERT_QUEUE_CAPACITY=5` 不一致，本次统一文档为 **5 条等待通知，不含当前展示项**，沿用现有实现容量。实际引脚与触摸以 SPEC-005/007 为准，不能使用 SPEC-003 的模块化参考引脚。

不包含自由走动、换装、养成数值、语音对话、在线下载动作、任意视频播放或云端 AI 自动编排。[视频播放验证](010-video-playback-probe.md)是独立实验，本动作系统不依赖 AVI/JPEG 解码器。

## 2. 动作与视觉验收

### 2.1 动作表

中文名仅用于说明；传输继续使用现有 `pet_action` 七个枚举，不增加 `happy`、`sad` 等别名。

| 动作 / 枚举 | 必须出现的角色变化 | 最少独立姿态帧 | 时间与结束方式 |
| :--- | :--- | :--- | :--- |
| 待机 `idle` | 原角色睁眼、眨眼、轻呼吸 | 2，保留原睁眼/闭眼资源 | 眨眼周期 5.3s、闭眼约 225ms；呼吸周期 2.4s，幅度 1px，持续循环 |
| 工作 `coding` | 低头看电脑，双手至少两种敲击姿势，间歇抬眼 | 4 | 2s 循环，至少含低头、交替敲击、抬眼；电脑不能是唯一差异 |
| 开心 `cheer` | 微蹲、举手、轻跳、落地、笑脸收势 | 6 | 入场动作 1.5s，只播一次；随后保持笑脸轻呼吸，直到通知关闭 |
| 叹气 `sigh` | 肩膀下沉、低头或垂眼、呼气、缓慢收势 | 4 | 入场动作 2s，只播一次；随后保持垂眼轻呼吸，直到通知关闭 |
| 警觉 `alert` | 抬头、睁大眼、身体绷直、短幅左右观察 | 4 | 1s 入场，随后 2s 低幅观察循环；不闪烁整屏；生命周期由通知优先级决定 |
| 睡眠 `sleep` | 闭眼、身体放松、缓慢呼吸；可有睡眠气泡 | 3 | 4s 循环；夜景，禁止循环发声；背光关闭时保留状态但停止无效刷屏 |
| 会议 `meeting` | 坐稳或收手的安静姿势，间歇眨眼 | 2，可复用合适的已有姿态 | 5.3s 眨眼循环，不打字、不跳跃、不主动发声 |

“独立姿态帧”要求眼睛、手臂或身体轮廓有可见变化；整图平移、缩放、星星或文字变化不能计入新的姿态。允许复用首尾姿态，不要求每个输出时刻都新画一张。

表内时间是逻辑时间。8 FPS 输出会量化显示时刻，允许最多一帧（125ms）的偏差；各关键姿态至少显示一帧。一次性动作不得因每帧重绘而重新入场。

### 2.2 角色、布局与声音

- 保留现有绿色角色的脸型、发型、服饰、像素风与色板，不用新的通用吉祥物替换。新增素材先与原角色并排预览，再做动作时间线预览。
- 主场景脚底基准 y=178；角色及动作粒子限制在 x=60..179、y=37..184，兼容现有呼吸帧的顶部边界。跳起不超过 8px，须通过收拢姿态预留向上位移空间；不得压住顶部、对话条、额度或裁掉手脚。静态原角色继续以最近邻从 67×120 显示为 78×140。
- medium 保留房间，真实事件摘要进入对话条，标题与倒计时按 SPEC-003 展示。开心和叹气的表情、姿态本身必须可辨认。
- high 继续覆盖房间，保留完整的告警标题、摘要和确认区域；增加紧凑警觉角色。角色区域 x=12..67、y=44..143，文字区域 x=80..227、y=44..179，确认区域 y=188..211。文字仍按字库边界换行/省略，角色不能遮字。
- 会议期间的 medium 使用安静变体：保留开心/叹气表情和小幅手势，禁止跳跃；动作类别与事件含义不变。high 仍显示警觉角色，但强制静音。
- 动画帧本身不触发声音。现有告警音频层根据 `sound`、优先级、静音和会议规则控制播放；切帧、循环和重复投递不得重复启动音效。不新增音效资源库，仍保留 high 既有告警音策略。
- 屏幕不展示未经校准的触摸操作承诺。动作动画不能阻塞后续确认事件。

## 3. 输入与事件映射

### 3.1 状态来源

1. `down/state`（QoS 1、retained）的 `data.work_mode` 决定持久基础状态：`idle`、`coding`、`meeting`、`sleep`。
2. `down/alert`（QoS 1、非 retained）沿用 `event_id`、优先级、有效期、`pet_action`、`sound`、`duration_sec`、标题和摘要。
3. 现有 `POST /api/v1/notify` 和 CLI 继续传上述枚举；不增加独立动作 MQTT 主题、HTTP 端点或第二条事件管道。消息仍受 SPEC-002 的 2048 字节上限约束。
4. `metrics.data.pet_mood_hint` 不覆盖基础模式或当前通知动作；额度更新不能凭空生成开心/叹气事件。

### 3.2 业务映射

| 输入 | 优先级 / 动作 | 结果 |
| :--- | :--- | :--- |
| 工作模式为 idle / coding / meeting / sleep | 对应基础动作 | 持续到下一次模式变化 |
| 命令或任务明确成功 | medium / `cheer` | 开心一次，保持收势，随通知结束恢复基础状态 |
| 命令或任务明确失败 | medium / `sigh` | 叹气一次；普通非零退出码不自动升级 high |
| 调用方明确指定严重告警 | high / 视觉统一 `alert` | 抢占当前动作，等待手动确认 |
| 调用方明确指定普通警觉通知 | medium / `alert` | 警觉动作，遵守普通通知倒计时 |
| low 通知 | 任意 `pet_action` | 只按既有规则打点或丢弃，不启动角色瞬时动作 |

成功/失败依赖已有包装器退出状态或明确事件字段，不解析标题语气猜测结果。通用 notify 继续尊重合法 `pet_action`；`idle/coding/meeting/sleep` 出现在 medium 内时，只临时呈现该动作，不能改写基础模式或过滤策略。

结构损坏、缺失必填字段、非法优先级的消息按协议拒绝。仅动作字段未知时，设备保留合法通知及其优先级，medium 回退当前基础动作，high 回退警觉动作并记录降级；不得因此隐藏告警。云端/CLI 仍严格校验并拒绝未知枚举。未知 `work_mode` 不覆盖最后合法模式；相同模式的重复同步不重置动画起点。

## 4. 调度与生命周期

### 4.1 唯一调度源

告警调度器唯一决定当前通知与等待队列；动画器只消费“最新基础模式 + 当前展示通知 + 单调时间”，不得自建等待动作队列。未获展示资格、被过滤、过期或被挤出的通知不能播放角色动作或声音。

基础模式始终更新；瞬时动作不能把旧模式写回。有效的 high > 当前 medium > 基础动作。medium 之间 FIFO 等待，不互相打断。

### 4.2 必须保持的行为

| 场景 | 规定行为 |
| :--- | :--- |
| high 打断 medium | 最迟下一次显示帧切为警觉；被打断 medium 丢弃，动作和音效都不续播、不重新排队 |
| high 期间收到不同 high | 立即替换内容与动作起点；原 high 不回队列 |
| high 期间收到 medium | 进入同一等待队列，等待 high 确认；出队再次检查模式和有效期 |
| 等待队列满 | 容量 5，丢最老的等待 medium；当前展示项不受此淘汰影响 |
| medium 结束 | `duration_sec` 从真正开始展示计算，3..60s，默认 8s；动作入场结束不能提前关通知 |
| high 动作循环结束、TTL 到期或网络断开 | 不自动关闭；必须继续展示直到既有确认机制消除 |
| 通知结束且有下一条 | 先完成出队过滤，再从下一条动作起点播放 |
| 通知结束且没有下一条 | 恢复此时最新基础模式，从该模式循环起点开始，不续播旧动作 |
| 基础模式在 medium 期间变化 | 更新底层状态；当前 medium 保留至原定结束，会议静音立即生效；进入 sleep 清除等待 medium，当前 medium 结束后恢复 sleep |
| 基础模式在 high 期间变化 | 更新底层状态，high 继续显示；进入 meeting 立即静音，进入 sleep 按既有 high 唤醒/音量规则处理；确认后恢复最新模式 |

模式过滤保持 SPEC-003：idle/coding 的 low 只打点，meeting 的 low 丢弃、medium/high 静音，sleep 的 low/medium 在入口直接丢弃、high 唤醒；出队按最新模式复核。通知内临时 `pet_action=sleep` 不等于系统进入 sleep。

### 4.3 重复投递、重连与时间

- 调度器在入口按 `event_id` 检查当前项与等待项，重复消息不重置倒计时、动作或音效。相同 ID 即使内容不同也视为重复，以首次接收内容为准。
- 为防止刚关闭的动作因 QoS 重投再次播放，在同一调度器维护最多 32 个已完成/已丢弃事件 ID，按单调时间保留 300s；满时淘汰最老项。去重窗口内有效，淘汰、超时或设备重启后不承诺历史去重；不写 NVS，不使用无界缓存。
- 开机先显示 idle 与连接状态；收到 retained 工作状态后切换。重连只同步状态，不重放历史通知。断网保持最新基础模式、正常结束当前 medium、保留当前 high；待机动画继续运行，离线标识如实显示。
- Unix 时间仅用于协议有效期等墙上时钟语义；动画、倒计时、去重窗口使用 64 位单调毫秒计时。SNTP 跳时不得让动作倒播、重新入场或让已展示 high 消失。尚未校时的通知准入沿用现有协议策略，不由动画器另行放宽。
- 显示阻塞后直接跳到当前应显示的帧，不逐帧补播。不以调用次数累计时间；重复采样相同输入和时间得到相同画面。

## 5. 实现边界与资源预算

### 5.1 共用实现

- 继续采用现有纯 C 动画/渲染模块与离线资源生成，ESP-IDF 设备和 SDL2 模拟器共用同一套逻辑；不为该功能引入 LVGL、视频解码或额外运行时依赖。
- 动画器负责动作阶段、帧索引、位置偏移与收势；渲染器负责组合房间、角色、文字和状态；音频/网络/确认行为不放进绘制函数。
- 网络回调、模式同步、通知 tick 与确认操作必须串行提交给唯一状态持有者；若保留多个执行上下文，需统一锁保护，并在显示帧起点复制完整场景快照。不得在 15 个条带之间重新读取可变的通知指针或切换姿态。
- 一个输出帧固定采样一次动作及字体/文本状态；15 条 strip 都使用该快照，避免上下半身来自不同帧。同步 flush 消费完毕后才允许复用缓冲区。
- 切模式、收通知只标记更新并退出，禁止在 MQTT 回调或显示任务内通过 `delay`/sleep 等待动画完成。资源失败时回退原 idle 资源；告警文字、确认和网络连接仍须工作。

### 5.2 预算与资源格式

| 项目 | 首版上限 / 验证要求 |
| :--- | :--- |
| 画布与刷新 | 240×240 RGB565，目标 8 FPS；不全屏频闪 |
| 条带缓冲 | 240×16×2 = 7680 字节；SPI 字节序/DMA 另用 7680 字节，继续同步提交 |
| 动画新增可写内存 | 相对同配置基线峰值增加 ≤16KiB，含新增状态、去重记录和资源工作区；禁止完整帧缓冲与运行期整包解码 |
| 新增只读动作素材 | RGB565 + 透明遮罩与描述表总计 ≤1MiB；去重存储，最多 48 幅独立姿态；以实际生成二进制字节计数 |
| 应用分区 | 以当前 `firmware/partitions.csv` 的 factory 3MiB 为准；最终应用 ≤2.75MiB，至少留下 256KiB 槽内余量，不改分区表 |
| 运行稳定性 | 动画循环不反复 malloc/free；连续运行 30 分钟无持续堆下降、看门狗复位或 MQTT 失联 |
| 物理性能目标 | 连续 60s 活跃动画平均 ≥7 FPS，渲染与同步刷屏耗时 P95 ≤125ms；记录实际值，未达标不得写成通过 |

源 PNG 与动作描述表保存在版本库；描述表至少包含动作 ID、画布尺寸、基准点、帧引用、各帧持续时间、循环/收势规则。生成器验证帧索引、尺寸、透明遮罩长度、时间非零、总预算后输出只读 C 数据；设备无需 PNG 解码器。

67×120、RGB565 加 1bit 遮罩约 16.7KiB/帧；现有遮罩格式或更大动作画布会改变实际开销，必须按最终数组计量，不能用这个估算代替链接报告。素材超限时优先复用帧和减少冗余，不自动扩分区或增加 PSRAM 依赖。

/* 示例接口形态，不是已存在的 API。时间相同，采样结果相同。 */

## 7. 验证策略与验收条件

### 7.1 必须覆盖的测试

| 层级 | 验证输入 | 通过条件 |
| :--- | :--- | :--- |
| 宿主 C 时间线 | 入场前后、每帧边界、循环边界、长时间跳跃、相同时间重复采样 | 无越界；一次性动作不重复入场；丢帧后直接定位；零时间漂移累计 |
| 调度回归 | 四基础模式 × 三优先级 × 七动作枚举 | 符合模式矩阵；临时动作不能改变基础模式；high 一律警觉，low 不启动瞬时动作 |
| 打断/恢复 | cheer 被 high 打断；high 期间 coding→sleep；两条 medium 排队后切 meeting | 不续播被打断动作；确认后恢复最新模式；排队项展示前不动，会议无声 |
| 通知生命周期 | medium 3/8/60s；high 超过有效期；入场结束但通知未结束 | 时间由展示起点计；high 不自动消失；动作结束不替代通知结束 |
| 去重与有界性 | 当前/等待/刚完成项重投、33 个历史 ID、窗口到期、队列第 6 条 | 不重复入场或发声；内存有界；淘汰行为符合第 4 节 |
| 时间和连接异常 | SNTP 前后跳、重连、动画中断网、长刷屏间隔、设备重启 | 无倒播/爆发补帧；不主动拉取历史通知；重启行为符合第 4 节 |
