# SPEC-009：ESP32 实物云端联调

- 目标：已连接 USB 的 ESP32-S3 使用已核验板级引脚，连接腾讯云 MQTT TLS，接收真实通知并请求用户确认显示与提示音。
- 前置：SPEC-005/007/008；用户授权实物联调；公网 8883 已验收。

## 契约

1. 写入前读取完整 8MiB Flash，校验长度及设备端摘要一致；备份与原始串口日志仅保存在忽略的 `.local/`（目录0700、文件0600）。设备 MAC 必须匹配 `d8:3b:da:4a:e9:84`。操作退出释放端口，异常尝试复位回应用；刷写或启动失败恢复已验证备份。
2. Wi-Fi 与设备专用 MQTT 密码通过 NVS `sprite` namespace 读取，不编译到应用、不输出到聊天或提交 Git。沿用云端已绑定逻辑 ID `esp32_c049ef`。配置缺失/超长时不启动网络，不自动擦除已有 NVS。
3. 自定义分区：NVS 0x9000/0x5000，PHY 0xf000/0x1000，factory 0x10000/0x300000。其余 Flash 不擦除；本轮不提供 OTA。写入包含新 NVS 分区镜像，旧配置由全片备份保护。
4. MQTT 使用 `mqtts://voice-code.yangguanxue.top:8883`，内建根证书校验主机名与有效期；禁止跳过验证，使用完整根证书包以覆盖实际链。SNTP 成功后再建立 TLS，断线自动重连；初始化 MQTT 后启动 Wi-Fi，避免连接事件先于客户端创建。
5. 显示/音频保持 SPEC-007 已核验引脚，产品触摸上报继续禁用。本轮不将占位静态桌宠或模拟指标宣称为完整产品。通知的渲染与音频完成记录 event_id，作为软件证据，物理效果需用户目视/听感确认。
6. 验收：构建与现有宿主固件测试通过；刷写校验；实机 Wi-Fi、SNTP、TLS、订阅与上线状态；HTTPS 通知 event_id 对应实机接收、展示和音频调用；重启后重新连接。用户确认显示和提示音前保留物理效果待验收。
7. NVS 生成必须以 UTF-8 字节计算长度与 CRC。ESP-IDF 5.1.2 的 CSV 字符串路径对中文使用字符长度，不能直接用于本设备配置；使用官方生成器的字节写入接口，覆盖中文 SSID 的长度/CRC 回归验证。串口复位前显式释放 DTR，避免保持下载模式。
