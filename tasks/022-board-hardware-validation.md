# TASK-022：核验实机板级配置

- 输入：[SPEC-007](../specs/007-board-hardware-validation.md)、本地恢复镜像、当前 USB 实机。
- 交付：去敏核验记录、统一板级引脚清单、更新 SPEC-005。
- 约束：保留用户现有源码改动；不输出凭证；每次探测退出都复位回原应用。
- 状态：显示及播放基线、粗边界照片已确认；卖家S3原理图已核对，补齐GPIO5触摸、GPIO15录音和背光电路。GPIO5原生电容600次读取完成，用户确认三次动作及回到Kimi；可靠动作关联/手势、录音、亮度曲线和长期稳定性仍未验收。规格更新至v1.3.0。

## 顺序和验证

1. 固定源码归档，对比镜像各区域 SHA256，记录实际一致范围。
2. 检查旧 NVS 的有效页、配置存在性和 EEPROM 亮度/方向，不输出网络名称或密码。
3. 备份当前 NVS 并用 `flash_md5sum` 校验，必要时恢复已备份旧 NVS；写后校验并复位。
4. 使用 mDNS、已知 DHCP/串口信息定位 HTTP 服务，不扫描大网段；状态结果白名单保存。
5. 音频低音量单声测试，必要时采用独立诊断；记录身份读取、驱动结果和用户观察。
6. 记录稳定性、触摸证据缺口；生成板级基线，运行 `git diff --check` 并核对文件链接。
7. 第二次 RAM 诊断延长到 60 秒，用户触摸配合期间只读输入寄存器，记录排除已知总线后的原始电平及变化候选。无明确关联则触摸继续禁用。
8. 连接中断后保留不完整结果，分别记录复位命令与应用启动证据；离线用 `python3 -m py_compile tools/board_probe/run_ram.py` 检查脚本语法，不因此再次操作设备。
9. 审阅新取得的 S3 整板原理图和屏幕规格书，核对 TP_KEY=GPIO5、录音数据=GPIO15、背光 AO3401 电路；屏幕型号必须核对 FPC 引脚，不能按目录名认定。更新资料来源、SHA256 和证据等级。
10. 仅配置原理图已证实的 GPIO5 原生触摸，编译 RAM 诊断，采集60秒原始计数。验收：空闲与三次按住/松开存在可重复变化且用户确认；退出复位、关闭端口。最终单击/长按、录音和背光亮度曲线另行验收。

执行结果见 `docs/hardware/2026-11-03-usb-inspection/board-validation.md`。
